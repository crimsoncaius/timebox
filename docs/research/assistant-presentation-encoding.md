# Assistant presentation encoding

Research for #237, 2026-09-21. Read-only source inspection and public metadata requests; no credentials or model inference calls were used.

Implementation follow-up (2026-09-22): subsequent live checks found that card-only responses omit the trailing newline. The user approved accepting a complete valid snapshot selector at confirmed successful model termination only. The newline remains mandatory before answer text. See the amended implementation handoff; the original research recommendations below predate that evidence.

## Finding

Recommend choosing the bounded JSON control line followed by plain text described below as the exact model encoding. It enforces selector-first order in application code and does not depend on unproven native schema-plus-tools behavior. Track a provider smoke check as an explicit implementation dependency before rollout: the design can be chosen now, but prompt adherence has not been empirically verified. Native structured streaming is a credible alternative, not a required assumption. Neither option requires another presentation tool or more than two model calls.

## Evidence

- The repository pins `langchain-openrouter` 0.2.8, `langchain-core` 1.6.3, and `openrouter` 0.11.46 in [backend/uv.lock](../../backend/uv.lock). [assistant_agent.py](../../backend/app/services/assistant_agent.py) binds the read tool only for the first call, optionally reads once, and makes a second unbound call. Its event translator currently forwards text from both calls immediately. Retries are explicitly disabled, including the SDK workaround.
- OpenRouter documents `response_format: {type: "json_schema", json_schema: {strict: true, ...}}` and streaming partial JSON. It advises capability checks and provider `require_parameters: true`; it does not establish the exact property ordering required by this application's UI. [Structured outputs](https://openrouter.ai/docs/guides/features/structured-outputs).
- The public [model catalog](https://openrouter.ai/api/v1/models), fetched on the research date, lists both `response_format` and `structured_outputs` for `z-ai/glm-5.3-flash`. The [endpoint catalog](https://openrouter.ai/api/v1/models/z-ai/glm-5.3-flash/endpoints) shows provider differences: DeepInfra advertises both; some providers advertise only `response_format`, while others advertise neither. Model-wide metadata is not an execution result for the route actually selected.
- The [versioned adapter source](https://github.com/langchain-ai/langchain/blob/langchain-openrouter%3D%3D0.2.8/libs/partners/openrouter/langchain_openrouter/chat_models.py) implements `with_structured_output(method="json_schema", strict=True)` through `response_format`, passes provider preferences, and implements asynchronous streaming through the SDK. Its default structured-output method is function calling, so it must be explicitly overridden. Inspecting these paths does not verify the pinned SDK and provider together. For incremental field parsing, bind `response_format` directly and consume raw content deltas rather than assuming the completed-object parser establishes field completion.

## Recommended application contract

Presentation is exactly `none` or one eligible server-owned snapshot reference. Validate the complete selector before emitting a complete card, then emit answer text. Never expose selector syntax or raw JSON to Android. Snapshot ownership, completed-history eligibility, current-read freshness, cardinality, and capability negotiation remain server checks even with strict model schemas. A card can precede an interrupted answer, but only confirmed completion followed by acknowledgement commits the exchange.

Do not equate receipt of a closing JSON fragment or a card with model completion. Reject malformed selectors, unknown references, duplicate selector fields, multiple cards, truncated output, and unsupported terminal reasons; retain visible partial output as an interrupted attempt under the accepted UX.

## Encoding candidates and streaming constraints

**Native schema candidate:** one object with `presentation` (a closed union of none or snapshot reference) and `answer` (string, empty permitted for card-only answers). Use strict schema enforcement and provider parameter requirements. A string enum of currently eligible references can constrain selection further, but server validation remains authoritative. An incremental parser must handle arbitrary chunk boundaries, JSON escapes and Unicode, detect duplicate keys, and distinguish a closed selector from a parser's provisional partial value. JSON object semantics do not promise property order: if answer arrives first, buffer it until the selector validates. Do not assume schema property order guarantees card-first emission. Full-response validation and terminal confirmation are still required.

**Bounded prefix alternative:** prompt the model to start its final answer with exactly one newline-terminated control line, for example `{"presentation":"none"}\n` or `{"presentation":"snapshot","snapshot_id":"<opaque server id>"}\n`, followed by plain answer text. Permit only the specified keys and literal discriminator values; reject duplicate keys, leading prose/fences, invalid IDs, missing newline, and a header exceeding a fixed small byte limit (for example 512 UTF-8 bytes). The parser buffers only that first line, emits a validated card once, then treats the remaining stream as answer text, never rescanning body text for controls. This is an application-enforced grammar, not provider-enforced structured output; malformed generation fails explicitly. Later textual imitations cannot trigger another card. The exact limit and grammar need parser tests and model smoke checks before adoption.

**First-call ambiguity applies to both:** the tool-capable first call may emit content before requesting the plan read. Buffer its content until the terminal tool/no-tool decision. If it requests the supported read, discard that content and execute the read; only the second call supplies presentation and answer. If it finishes without a tool call, validate and release its buffered presentation/answer. Thus the no-read path may be delivered after generation rather than token by token. Do not simulate streaming or promise universal token streaming. The post-read second call can stream text after its selector validates because it has no tools; unexpected tool output remains an error.

## Verification gate

The user accepted the bounded JSON control line followed by answer text. Before release, run a small explicitly budgeted smoke check of that chosen encoding through the pinned adapter/SDK and chosen routing settings: no-card answer, current read plus card/text, card-only answer, and historical reference. Observe prefix compliance, selector/answer arrival order, finish metadata, and that no extra model calls or automatic retries occur. Failure is a release blocker to investigate, not authorization to silently switch encoding or retry. Native schema encoding is an unselected alternative.

Offline parser tests should split control syntax and escapes at every boundary and cover answer-before-selector, malformed/duplicate keys, unknown IDs, truncation, cancellation after card, tool-call preamble disposal, and late output after reset. These can establish server behavior independently of model reliability. No live smoke check was performed in this research, so provider compatibility remains an explicit implementation gate rather than a claimed completed validation.
